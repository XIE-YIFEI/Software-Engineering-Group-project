# SECS Vision 网页系统：需求规格说明

[English version / 英文版](REQUIREMENTS_EN.md) · 系统文档目录：[索引](README.md)

## 1. 目的与范围

本项目的识别代码（`alpr/`）把摄像头视频变成结果文件：图片和视频里读到的车牌、模拟登记库产生的告警、按车型和车道的车流、
危险驾驶事件、高峰拥堵预测。本说明书描述建在这些结果之上的**网页系统**（`webapp/`）：数据库、API、四种角色的页面、
处理新上传文件的后台任务，以及持续集成（CI）。

定位：*把摄像头视频变成可以检索、会告警、能预测拥堵的交通数据*。

**本次范围：** 登录与角色；总览；车牌检索与记录；告警中心；交通分析；拥堵预测；上传与分析；名单；隐私与审计；报表；
以及商定的六项补充功能（按角色打码车牌、点击跳到视频对应时刻、门岗模式、限时访客通行证与超时滞留、跨摄像头时间线、
证据包）和“多开车道会怎样”的推演（what-if）。
**已预留设计、本次不实现：** 实时 RTSP 摄像头、在浏览器里画车道、不含车牌的公众拥堵预报页、推送通知、生成式 / 智能体
AI 助手（下一个任务）。

## 2. 用户及其收益

| 用户 | 现在的问题 | 系统提供什么 |
|---|---|---|
| **交警 / JPJ 执法人员**（角色 `police`） | 被标记的车辆经过摄像头没人发现；要知道某个车牌在何时何地出现，只能一段段翻视频 | 黑名单、套牌、未登记、路税过期、车型不符的车牌告警，以及车道违规告警，按严重程度排序；容错的车牌模糊检索，点击直接跳到视频对应秒数；跨摄像头时间线；证据包 |
| **公寓 / 写字楼门岗保安**（角色 `guard`） | 保安手写车牌登记；访客超时滞留没人发现 | 门岗卡片把每辆到达车辆显示为绿 / 青 / 黄 / 红；一键记录放行；带有效时段的访客通行证；超时滞留置顶；可检索的进出记录 |

## 6. 非功能需求

| 编号 | 需求 | 如何满足 / 如何度量 |
|---|---|---|
| NFR-1 隐私 | 遵循马来西亚《2010 年个人数据保护法》（PDPA）的数据最小化原则（个人数据对处理目的而言充分但不过量，第 6(3)(c) 条；保存时间不超过实现目的所需，第 10(1) 条）。PDPA 不适用于联邦政府和州政府（第 3(1) 条），所以系统**不**声称警察或 JPJ 的使用受它约束；对这些角色同样施加这些控制，作为良好做法。 | 角色限定；打码；查看需理由；保留期限；审计；门岗数据只有车牌、单元号和简短标签（不存姓名或身份证号）。条文已在官方文本中核对（Laws of Malaysia, Act 709，截至 2016 年 6 月 15 日的在线更新文本）；2024 年修订案未针对这些条文重新核对。 |
| NFR-2 安全 | 密码不以明文保存；会话可撤销；防跨站请求 | scrypt；只保存会话令牌的 SHA-256；HttpOnly、SameSite=Lax 的 Cookie；CSRF 请求头；登录锁定；服务器默认只监听 127.0.0.1，在其他地址启动且演示账号仍启用时给出警告 |
| NFR-3 诚实 | 真实数据与模拟数据绝不混在一起 | 每条观测都有 `provenance`（camera / inserted_plate / synthetic）；每个页面、CSV 和 PDF 都有紫色“Simulated”标记；`UNMATCHED`、登记库和推演都附有说明 |
| NFR-4 性能 | 演示数据上页面可交互；数据量大时检索仍可用 | 实测（见测试报告）：总览、检索、告警、时间线和预测面板的响应时间中位数 20–65 ms；在 10 万个不同车牌中模糊检索 34 ms（精确）/ 130–140 ms（容错 1–2）；PDF 证据包约 1.5 秒 |
| NFR-5 可靠性 | 一次分析出错不能拖垮服务器 | 后台任务在子进程里运行识别流水线；失败记录在任务上；服务器停止时仍在运行的任务，重启后标记为失败 |
| NFR-6 可维护性 | 同学能在此基础上扩展 | 分层（数据访问 → 服务 → API / 页面）；带类型的模型；SQL 集中在一处；不需要前端构建工具；86 + 22 个自动化测试；每次推送都跑 CI |
| NFR-7 可移植性 | 能在组员的笔记本上运行 | Windows 11 + Python 3.12 虚拟环境（已测试）；CI 用 Ubuntu；只用 CPU；运行时不需要联网（不依赖 CDN） |
| NFR-8 易用性 | 外观统一；导航按角色区分 | 沿用现有仪表盘（`alpr/hud.py`）的深色风格和配色；界面为英文；每个图表都有表格视图 |
| NFR-9 可审计 | 日志被改动一定会被发现 | 只追加的触发器；每行带上一行的哈希；管理员可“校验哈希链” |

## 7. 数据及其局限（数据缺口）

| 数据 | 真实还是模拟 | 局限 |
|---|---|---|
| 路边、门岗和车道视频里的车牌 | 真实（YouTube 公开视频） | 演示片段 30–155 秒；时钟是设定的（视频本身没有录制时间） |
| 车辆登记库 | **模拟**（`alpr/registry.py`） | 无法接入 JPJ；真实车牌一律是中性的占位记录；`UNMATCHED` 只表示“不在模拟登记库里” |
| 违规车辆 | **虚构的 X 开头车牌**（以及格式错误的 `WXY 12345`），插入视频或完全合成 | 真实车辆的违规被隐去（只计数，不显示） |
| 跨摄像头出现记录 | **模拟**（XSD 4004 出现在新山） | 我们的几个摄像头地点和日期都不同，没有任何真实车辆出现两次 |
| CIQ 拥堵数据 | 真实测量（2 天、2 个摄像头、1 条路） | 只有占有率 / 占满程度，没有每分钟车辆数和车速（TEAM_GUIDE 10.6）；预测只在 2 天上验证 |
| 门岗离开记录 | 人工（保安点“Exited”）或模拟 | 出口车道的车牌太小、角度太斜，读不出来 |

## 8. 局限（如实说明）

- 登记库是模拟的（无法接入 JPJ），真实车牌不可能产生告警，所以演示中的每条告警都针对虚构车牌。
- 只用 CPU 时分析速度约 10 FPS（OpenVINO、无界面模式）；要实时需要 GPU（TEAM_GUIDE 第 11 节）。
- 演示视频是公开视频，所以真实车辆的违规被隐去；无法展示带车牌的超速证据（车道摄像头读不出车牌）；证据包用违规演示里的
  虚构车牌来演示。
- 推演是在所述假设下的确定性点排队模型，不是交通仿真；其中的放行能力是粗略的下限估计或人为假设。
- 证据包是课程演示，不是官方文件；其中的哈希只能证明图片在导出之后没有被改动。
- 本地部署：SQLite、单台服务器、127.0.0.1 上的普通 HTTP；在允许其他电脑访问之前，必须先停用公开的演示账号。
- 上传的视频只有 H.264 编码的 MP4 能直接在浏览器播放（其他格式会用自带的 ffmpeg 另存一份 H.264 副本）。
